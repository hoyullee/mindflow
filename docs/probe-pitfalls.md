# 프로브 함정 — 검증이 거짓말을 하는 자리들

실브라우저 프로브(Playwright·CDP)·테스트 하네스·로컬 검증에서 **앱이 아니라 프로브가 틀렸던**
사건들을 모았습니다. 전부 이 저장소에서 실제로 겪은 것이고, 값은 실측입니다.

## 첫 번째 규칙

> **검증이 실패하면, 앱을 의심하기 전에 프로브를 의심한다.**

이 목록의 절반은 앱이 결백했던 사건입니다. 그리고 오진의 비용은 작지 않았습니다 —
`addInitScript` 재실행 하나에 **2시간**, 페이드 중 스크린샷에 **1시간**, CDP 키 이벤트에
**30분**을 잃었고, 같은 함정을 **네 번** 다시 밟은 것도 있습니다.

수리에 들어가기 전에 스스로 묻습니다: **이 실패가 앱 버그라면, 사용자가 손으로 했을 때도
같은 일이 일어나는가?** 아니라면 프로브를 고칠 차례입니다.

## A. 상태 주입·시드

<a id="a1"></a>
### A1. `addInitScript`는 리로드에도 재실행된다 — **네 번 재발**

가장 비싼 함정입니다(첫 사건에서 **2시간**을 잃었고 앱은 무결했습니다). 시드 스크립트가
매 내비게이션마다 다시 돌아 저장소를 원래 값으로 덮으므로, **"리로드하면 방금 바꾼 것이
되돌아간다"가 앱 버그처럼 보입니다.**

```js
// 나쁨 — 리로드마다 덮어쓴다
await page.addInitScript(() => localStorage.setItem('mf_x', JSON.stringify(seed)))

// 좋음 — 없을 때만 심는다
await page.addInitScript(() => {
  if (!localStorage.getItem('mf_x')) localStorage.setItem('mf_x', JSON.stringify(seed))
})
```

그리고 **리로드로는 주입값을 바꿀 수 없습니다**(테마·설정을 바꿔 심으려면 새 페이지로 열 것).

<a id="a2"></a>
### A2. init script는 페이지 생성 **전에** 붙인다 / 그 시점에 `documentElement`는 null

`page.addInitScript`는 그 뒤에 만들어진 페이지에만 적용됩니다. 그리고 스크립트가 실행되는
시점에는 `document.documentElement`가 **아직 없어서** 그것을 `MutationObserver`로 관찰하면
조용히 아무것도 못 봅니다 — `document`를 관찰하세요.

<a id="a3"></a>
### A3. 시드는 **실물 모양 그대로**

손으로 지은 시드는 실앱이 절대 만들지 않는 상태를 만듭니다:

- 칸반 `tags`에 `id`를 빠뜨려 **에디터가 CRDT 동기화에서 통째로 죽었다**(실앱은 항상 id를 만든다)
- 워크스페이스 블롭에 `extra`가 없어 **두 라운드를 헛돌았다**
- 문서 `themeKey`를 실제 값(`white`)이 아닌 `coral`로 심어 **색 버그가 재현되지 않았다**

실제 저장본을 한 번 떠서(브라우저에서 `localStorage.getItem(...)`) 그 모양대로 쓰는 편이 빠릅니다.

**필드 이름 하나가 통째로 헛돌게 합니다**(이번 라운드 실측): 링크 런의 필드는 `href`인데
`lk`로 심었습니다(직렬화된 어느 화면에서 본 이름이었습니다). 그 값은 조용히 무시돼 화면에는
평범한 글자가 그려졌고, 초점을 잃을 때 그 평문이 그대로 커밋됐습니다 — 저는 그것을 **"링크가
사라지는 심각한 버그"**로 읽고 한참을 쫓았습니다. 시드가 앱이 만들지 않는 모양이면 앱은
결백합니다. 필드 이름은 **`model.ts`에서 확인**하세요.

<a id="a4"></a>
### A4. **저장본을 읽어 결과를 판정하지 않는다** — 자동저장은 늦는다

`localStorage.getItem('mindflow_doc_…')`로 방금 한 편집의 결과를 재면 **직전 값**이 나옵니다.
자동저장에 디바운스가 걸려 있어 조작 직후에는 아직 쓰이지 않았기 때문입니다. 실측: 굵게를
건 뒤 400ms·500ms 뒤에 읽어 둘 다 "안 걸렸다"로 읽었고, 그래서 **멀쩡히 동작하는 여러 줄
서식을 "적용되지 않는다"로 오진**했습니다(3초 뒤에 읽으니 전부 맞게 들어 있었습니다).
게다가 그 값은 **한 판 전의 결과**라 "다음 케이스에 앞 케이스의 흔적"이 섞여 보입니다 —
제가 실제로 그 흔적을 새 증상으로 착각하고 쫓았습니다.

- **DOM에서 재세요**(비제어 편집 박스는 화면이 곧 결과입니다) — 또는
- 저장이 끝날 때까지 **폴링**하세요(값이 바뀔 때까지), 고정 대기는 다음에 또 틀립니다.

## B. 이벤트 합성

<a id="b1"></a>
### B1. CDP로 넣은 키는 `before-input-event`를 지나지 않는다 (Electron)

Playwright `keyboard.press`로 넣은 키는 메인 프로세스의 `before-input-event`에 **한 건도
도달하지 않습니다.** 그것만 보고 "단축키 차단이 동작하지 않는다"고 **30분** 오진했습니다.
실제 키보드와 같은 경로는 **`webContents.sendInputEvent`**입니다.

<a id="b2"></a>
### B2. 합성 드래그는 이벤트 사이를 띄운다 — **두 번 재발**

`dragstart`→`dragover`→`drop`을 한 `evaluate`에서 동기로 쏘면 React가 상태(`dragIdx`)를
커밋하기 전에 drop이 도착해 **재배치가 안 된 것처럼 보입니다.** 실사용자의 드래그에는
이벤트 사이에 프레임이 있습니다 — 프로브도 사이를 띄우세요.

<a id="b3"></a>
### B3. 수정 키는 `modifiers`로 넘긴다

`keyboard.down('Shift')` + `mouse.click`에는 **`shiftKey`가 실려 오지 않습니다.**
`page.click(sel, { modifiers: ['Shift'] })`를 쓰세요.

## C. 측정 타이밍

<a id="c1"></a>
### C1. 전이·애니메이션 **도중**에 재면 틀린 값이 나온다

실제로 오진을 만든 것들(전부 이 저장소의 값):

| 무엇 | 길이 | 도중에 재면 |
|---|---|---|
| 카드 hover 떠오름 | 0.18s | 사각형이 **3px** 어긋난다 |
| LNB 행 배경 | 0.14s | 색이 중간값(반투명)으로 읽힌다 |
| 팝업 `mf-fade` + `useCardMorph` | 0.2s / 0.24s | 카드가 **6px 아래**, 내용이 잘려 보인다 |
| 대시보드 등장 | 0.3s | 스크린샷이 전부 워시로 나온다 |
| 배너 페이드 | 0.25s | 반투명이라 **스태킹 순서를 오판**(1시간 조사) |

계산값(`getComputedStyle`의 색)은 대개 무관하지만 **좌표·스크린샷은 가라앉은 뒤에** 재세요.

<a id="c2"></a>
### C2. 프레임 샘플러의 `t0`는 `__start()`에서 잡는다

init script 시점에 잡으면 관찰 창이 이미 지나가 **1프레임만** 기록됩니다.

<a id="c3"></a>
### C3. "현재 DOM"으로는 지나간 것을 못 본다

마운트 커밋과 데이터 커밋이 같은 태스크에서 일어나면, 그 뒤에 DOM을 다시 조회해 봐야
언제나 "그런 노드는 없었다"로 보입니다(스켈레톤이 정말 떴는지 확인할 때 겪었습니다).
**추가된 노드를 기록**하세요(`MutationObserver`로 `addedNodes` 수집).

## D. 좌표·히트 테스트

<a id="d1"></a>
### D1. 뷰포트 밖 1px이면 `elementFromPoint`는 NONE

붙여넣은 사본이 `x=1501`(뷰포트 1499)에 걸려 히트가 비었고, 드래그가 허공을 잡아 **팬으로
빠졌습니다.** 배터리 한 단계가 계속 실패한 원인이 그것이었습니다 — 대상 좌표를 화면 **안쪽**으로.

<a id="d2"></a>
### D2. 실브라우저의 뷰포트 요소는 (0,0)이 아니다

캔버스 좌표를 계산할 때 앱의 `toCanvasPoint`가 빼는 rect를 **프로브도 더해야** 합니다.
jsdom에서는 그 값이 0이라 이 어긋남이 드러나지 않습니다.

<a id="d3"></a>
### D3. 기울어진 요소는 bounding box가 부푼다

드래그 고스트처럼 `rotate(1.5deg)`가 걸린 요소는 `getBoundingClientRect().width`가 실제보다
큽니다 — 폭 비교는 **`offsetWidth`**로.

그리고 `offsetWidth - clientWidth`에는 **테두리가 포함**됩니다(1px 테두리 양쪽을 "스크롤바 2px"로
읽은 적이 있습니다).

<a id="d5"></a>
### D5. `Range`의 사각형은 인라인 스팬의 **padding까지** 센다 — 글자 자리가 아니다

형광펜(제보 51-①)을 확인하려고 줄 전체를 감싼 `Range`의 폭을 서식 전후로 쟀더니
**3.47px 늘었다**고 나왔다. 실제로는 글자가 0.015px도 움직이지 않았다 —
`.mf-hl`이 `padding: 0.02em 0.12em`에 `margin: 0 -0.12em`이라 **글자 자리는 그대로**이고
스팬의 상자만 좌우로 0.12em씩 넓다. `Range.getBoundingClientRect()`는 그 안에 든
**요소들의 border box**를 합치므로 padding이 그대로 더해진다(0.24em × 14.5px = 3.48px —
관측값과 소수점까지 맞는다).

**글자가 움직였는지 보려면 글자를 재라**: 서식을 건 구간 **바깥**의 글자 몇 개만 감싸는
`Range`를 만들어 그 `x`·`y`를 전후로 비교한다(형광펜을 앞 세 글자에만 걸고 줄 끝 두
글자를 쟀더니 `dx=0.015 dy=0`). 아래 줄의 `y`도 함께 보면 "위로 틀어진다"는 제보가
글자의 일인지 줄 상자의 일인지 한 번에 갈린다.

<a id="d4"></a>
### D4. 그 자리에 이미 다른 것이 있다

- **달력 칸 가운데**에는 칩이 있습니다 → 칸을 누르려면 **좌상단 모서리**를. 칩을 잘못 누르면
  상세 팝업이 뜨고 **그 막이 이후 클릭을 전부 가로채** 연쇄 실패가 납니다.
- **속성 시트를 열면 대상이 시트 위로 재중앙 정렬**됩니다 → 고정 좌표를 누르면 "빈 곳"이 아니라
  그 대상을 누르게 됩니다("바깥을 눌러도 안 닫힌다"의 정체). 빈 지점은 **그때 찾아서** 누르세요.

## E. 환경 차이

<a id="e1"></a>
### E1. 헤드리스 크로뮴은 웹킷 커스텀 스크롤바를 그리지 않는다

오버레이 스크롤바가 강제돼 폭이 **0**으로 나오고, `::-webkit-scrollbar` 커스텀이 화면에
아예 반영되지 않습니다. 앞선 검증이 통째로 헛돌았습니다 → **xvfb headed 크로뮴**으로 재검증.

<a id="e2"></a>
### E2. 헤드리스는 `Notification.permission`이 늘 `denied`

OS 알림 경로(생성자 호출 여부)를 확인하려면 **xvfb headed**가 필요합니다.

**웹 푸시는 그래서 통째로 막힌다**(0040에서 실측): `pushManager.subscribe()`가
권한을 요구하므로 `AbortError: Registration failed - permission denied`로 끝납니다 —
Playwright의 `permissions: ['notifications']`를 줘도, `--headless=new`로 바꿔도
같았습니다. 그래서 **푸시의 실제 배달(푸시 서비스 → SW → 배너)은 이 환경에서
검증할 수 없습니다.** 대신 갈라서 확인합니다: 후보 고르기 SQL은 로컬 Postgres
하네스로, 구독 로직은 가짜 `pushManager`로, SW 조각은 **그 파일을 그대로 실행해**
(`new Function('self','clients', src)`) 핸들러를 부르는 식으로. 배달 자체는
"확인할 수 없다"로 보고하고 실기기 확인을 남깁니다(§H의 규칙).

<a id="e3"></a>
### E3. 컨테이너 TZ와 페이지 TZ가 다르다

페이지는 `Asia/Seoul`, 프로브는 컨테이너 TZ입니다. 자정 근처에 `new Date()`로 만든 "오늘"을
셀렉터에 쓰면 **하루 어긋나** "오늘 칸인데 오늘이 아니다"로 오진합니다.
**앱이 아는 오늘은 DOM에서 읽으세요**(`[data-day-cell][data-today]`).

<a id="e4"></a>
### E4. 이 컨테이너는 리눅스다

데스크톱 타이틀 바·트레이 메뉴·네이티브 토스트·로그인 항목·MSIX 서명은 **설계대로 그려지지
않습니다.** 플랫폼 게이트를 임시로 열어 확인해야 한다면 **컴파일 산출물에서만**(소스 무변경)
열고 곧바로 되돌리세요. 확인할 수 없는 것은 **"실기기 확인 필요"로 적고 넘깁니다.**

<a id="e7"></a>
### E7. 헤드리스는 **글자 커서(캐럿)를 스크린샷에 그리지 않는다**

"커서가 보이지 않는다"는 제보를 픽셀로 확인하려다 두 번 헛돌았습니다. 캐럿이 **분명히 있는**
대조군(글자가 든 줄에 캐럿을 놓고 focus)을 12프레임 찍어도 어두운 세로줄이 **0개**였습니다 —
창이 포커스를 갖지 못하는 헤드리스에서는 캐럿이 아예 칠해지지 않습니다.

그래서 캐럿의 **보임**은 이 환경에서 검증할 수 없습니다. 대신 **DOM 자리**로 가릅니다:
`getSelection().focusNode.nodeType === 3`(텍스트 노드 안인가) · `caretColor` 계산값 ·
초점 요소. 요소 경계에 놓인 캐럿은 사각형이 비어서 오고(§D와 같은 계열) 브라우저가
그리지 않는 경우가 있으므로, **"텍스트 노드 안에 있는가"가 실전에서 가장 쓸모 있는 잣대**입니다.
보임 자체는 "확인할 수 없다"로 보고하고 실기기 확인을 남깁니다(§H).

<a id="e8"></a>
### E8. `overflow-y: auto`만 줘도 **가로가 `auto`가 된다**

한 축만 `auto`로 두면 다른 축의 `visible`이 **`auto`로 계산됩니다**(CSS 규칙). 인라인
스타일만 읽고 "가로는 안 보이게 해 뒀다"고 믿으면 틀립니다 — 실측으로 본문 판의
`overflow-x` 계산값이 `auto`였고, 그 때문에 세로 막대가 생겼다 사라질 때마다 폭이 오가며
가로 막대가 따라 깜빡였습니다. **계산값을 읽으세요**(`getComputedStyle(el).overflowX`).
그리고 이 되먹임은 **오버레이 스크롤바인 헤드리스에서는 재현되지 않습니다**(§E1) —
막대가 폭을 먹지 않으므로 고리가 성립하지 않습니다.

**다만 `scrollbar-gutter: stable`은 헤드리스에서도 자리를 잡습니다**(실측: 같은 판이
`auto`일 때 708px, `stable`일 때 702px). 막대 자체는 오버레이라 보이지도 폭을 먹지도
않는데 **예약된 자리는 진짜**라, "고쳤다"의 증거로 쓸 수 있는 유일한 값입니다 —
깜빡임 자체는 못 봐도 **폭이 상수가 되었다**는 것은 잴 수 있습니다. 대조군(그 속성을
`auto`로 되돌려 길 때/짧을 때 폭을 견주기)을 함께 찍어 두면 "이 환경에서는 애초에
갈리지 않는다"는 사실까지 기록에 남습니다.

<a id="e9"></a>
### E9. 스크롤바가 걸린 증상은 **xvfb headed**로 내려가라 — 이 컨테이너에 있다

§E1이 "xvfb headed로 재검증"이라고 적어 두었는데도 헤드리스로만 세 번 헛돌았습니다.
`xvfb-run -a --server-args="-screen 0 1400x1000x24" node probe.mjs` + `headless: false`면
**폭을 먹는 15px 클래식 막대**가 나옵니다(실측: 헤드리스 0px → xvfb headed 15px).
Chromium 플래그(`--disable-features=OverlayScrollbar` 등)로는 **바뀌지 않습니다** — 세 벌을
시도했고 전부 0px이었습니다.

그리고 xvfb로 내려가면 **콘솔이 말을 해 줍니다**: 그 판에서야 행 그립을 끌 때마다
리액트가 `Maximum update depth exceeded`(프로덕션 번들에서는 `Minified React error #185`)를
던지는 것이 보였습니다 — 헤드리스에서 재현하지 못한 "깜빡임"의 유력한 정체였고,
잡는 데 든 비용의 대부분은 **있는 도구를 안 쓴 값**이었습니다. 프로브를 붙일 때
`page.on('pageerror')`와 `page.on('console')`를 **언제나** 걸어 두세요.

<a id="e10"></a>
### E10. "깜빡인다"는 **막대가 있나/없나를 프레임마다** 세어야 잡힌다

스크롤바 깜빡임을 세 라운드 동안 못 찾은 이유는 잣대가 틀려서였습니다. 나는
`offsetWidth - clientWidth`(막대 폭)와 `scrollWidth > clientWidth`(넘침)를 **판마다**
찍었는데, 정작 출렁이던 것은 **문서 전체의 높이**였습니다. 표의 가로 막대가 켜지면
그 판이 9px 높아지고 그만큼 `document scrollHeight`가 오갑니다 — 그 한 줄을 찍자
`1274 ↔ 1283`이 **프레임마다** 뒤집히는 것이 한눈에 보였습니다(한 번의 드래그에서
막대가 42번 토글).

그래서 프레임 샘플러에는 셋을 함께 넣으세요: **① 페이지 `scrollHeight`
② 각 판의 `offsetHeight - clientHeight`(막대가 먹는 높이) ③ `scrollTop`**.
①이 프레임마다 같은 폭으로 오가면 그것이 곧 깜빡임이고, ③이 ±로 뒤집히면 본문이
통째로 튀고 있는 것입니다(바닥까지 스크롤해 둔 상태에서 문서가 줄면 브라우저가
`scrollTop`을 잘라 냅니다).

<a id="e11"></a>
### E11. 리액트가 그리는 요소에 **인라인 스타일을 손으로 쓰지 마라**

드래그 동안만 `pane.style.overflowX = 'scroll'`로 못박았더니 토글이 42 → **2로 줄었을
뿐 0이 되지 않았습니다.** 그 요소의 `style`은 리액트가 렌더마다 다시 적어, 다음
프레임에 우리 값을 지웁니다. 상태로 올려 **선언적으로**(`overflowX: live ? 'scroll' : 'auto'`)
쓰면 0이 됩니다. "고쳤는데 덜 고쳐졌다"면 리액트가 덮고 있는지 먼저 보세요.

<a id="e12"></a>
### E12. `Range`의 사각형은 **캐럿이 어느 행에 보이는지** 말해 주지 않는다

감긴 줄의 랩 지점은 **한 오프셋에 두 자리**입니다 — 앞 행의 끝이자 뒷 행의 머리(글자 수로는
같은 자리). 어느 쪽에 그릴지는 브라우저가 쥔 **affinity**가 정하는데, `Range`의
`getBoundingClientRect()`는 그것을 **무시하고 언제나 앞 행 끝**을 돌려줍니다.

그래서 "→ 로 걸어가며 사각형을 찍는" 프로브는 **늘 「행 끝에 잘 선다」고 답합니다** — 실제
화면에서 캐럿이 뒷 행 머리로 뛰고 있어도 그렇습니다. 이 함정으로 제보를 한 번 "재현되지
않는다"로 접을 뻔했습니다(여섯 벌의 측정이 전부 같은 거짓 PASS를 냈습니다).

증거: 뒷 행에서 `Home`을 눌러 **뒷 행의 머리**로 간 직후에도 사각형은 앞 행 끝
(`top=28, left=424`)을 가리켰습니다. 캐럿은 분명히 아래 행에 있었습니다.

**가르는 법** — 「줄 끝으로」 이동이 어디로 가는지 봅니다:

```js
const before = offsetOf(sel)
sel.modify('move', 'forward', 'lineboundary')
const same = offsetOf(sel) === before   // true면 앞 행(upstream), 움직였으면 뒷 행(downstream)
```

실측(같은 자리, 도착 방법만 다름): 한 글자 `→`로 닿으면 44 → **88**(뒷 행 끝까지 뛴다 =
뒷 행에 있다), `lineboundary` 이동으로 닿으면 44 → **44**(제자리 = 앞 행에 있다).
스크린샷은 답이 되지 못합니다 — 캐럿은 xvfb headed에서도 찍히지 않습니다([E7](#e7),
`caret-color`를 빨강으로 바꿔 14프레임을 훑어도 한 픽셀도 나오지 않았습니다).

<a id="e5"></a>
### E5. 앱의 규칙을 모르면 프로브가 틀린다

최근 항목 트레이의 카드는 **일부러** 메뉴가 없는 바로가기입니다. 우클릭 프로브가 그 카드를
잡으면 메뉴는 영영 뜨지 않습니다 — 그리드 카드를 지정해야 합니다.

<a id="e6"></a>
### E6. 로컬/데모 모드에서 `mindflow_doc_<id>`는 **저장소 자신**이다

그 키를 지운 뒤 Ctrl/⌘+S를 누르면 `prevVersion`을 든 저장이 "행이 없다"로 실패하는 것이
**정상**입니다. 저장 여부를 보려면 키를 지우지 말고 **편집을 만든 뒤 저장본을 비교**하세요.

## F. 테스트 하네스(jsdom·vitest)

<a id="f1"></a>
### F1. jsdom에는 레이아웃 엔진이 없다 — 모든 사각형이 0

크기·줄바꿈·시프트는 여기서 검증할 수 없습니다(실브라우저의 몫). 게다가 **Radix는 "포인터가
하위 메뉴로 향하는가"를 그 사각형으로 판단**하므로, `userEvent`가 함께 쏘는 `pointermove`가
하위 메뉴를 **닫아 버립니다**(요소가 클릭 전에 DOM에서 떨어진다) → 플라이아웃 안 항목은
`fireEvent.click`으로 누르고, 마우스 경로는 실브라우저에 맡기세요.

포털(Radix Dialog·Popover·Menu)로 나간 것은 `container.querySelector`로 찾을 수 없습니다 —
`document`에서 찾고, Escape도 `window`가 아니라 `document`에 쏘세요.

<a id="f2"></a>
### F2. `new Response('', { status: 204 })`는 **생성 자체가 throw**

Fetch 스펙상 204는 본문을 가질 수 없습니다 — `new Response(null, { status: 204 })`.
(앱의 204 처리는 결백했습니다.)

<a id="f3"></a>
### F3. 클래스 인스턴스 스프레드는 프로토타입 메서드를 잃는다

```ts
{ ...new LocalShareStore(), list: vi.fn() }   // 나쁨 — 나머지 메서드가 사라진다
Object.assign(new LocalShareStore(), { list: vi.fn() })  // 좋음
```

당장은 통과하다가 **소비처가 새 메서드를 쓰기 시작하는 순간** 세 파일이 함께 터집니다.

<a id="f4"></a>
### F4. fake timer가 바꾸지 못하는 시간이 있다

`lib0/time`(y-protocols 계열)은 **모듈 로드 시점에 진짜 `Date.now` 참조를 잡아 둡니다.**
그래서 `lastUpdated`는 실시간, 나이 계산은 가짜 시간이 되어 "30초 타임아웃이 62초에도 안 돈다"가
됩니다(라이브러리는 결백). 그런 타임아웃은 fake timer 대신 **동작을 흉내 낸 버스**로 검증하세요.

<a id="f5"></a>
### F5. 시계 의존 테스트는 앵커로 만든다

`Date.now() - 2h`로 "오늘 항목"을 심으면 **자정~새벽 2시에 돌릴 때 어제가 되어** 깨집니다
(01:05 UTC CI에서 실제로 깨졌습니다). **오늘 09:00 같은 앵커**를 쓰고, 그 시각이 아직 오지
않았으면 `지금`으로 물러나세요. 상대 시각 문구(`2시간 전`)만 단정하는 테스트는 날짜와 무관합니다.

같은 계열로 **달 경계**도 있습니다. 이 저장소의 `shiftInMonth(n)`은 `오늘+n`이 달을 넘으면
**`오늘-n`으로 물러섭니다**(달력 격자 단정이 이 달을 기준으로 세기 때문). 그래서 미래로 두려던
날이 조용히 **과거**가 되고, "다가오는 마감"처럼 `due >= 오늘`을 보는 목록에서 그 항목이 통째로
빠집니다 — 9/12에는 통과하고 **9/13에 깨졌습니다**(`13+18 = 10/1` → `8/26`). 그 단정이 달에
매이지 않는다면 클램프 없는 `shiftDays`를 쓰세요. **PR CI가 통과한 커밋이 몇 시간 뒤 기본
브랜치에서 깨진다면 날짜부터 의심합니다.**

<a id="f6"></a>
### F6. jsdom은 **실기기가 만들 수 없는 상태**도 순순히 답해 준다

`Object.defineProperty(document, 'visibilityState', …)`로 `hidden`을 심고 테스트 11건을
통과시켰는데, **실기기(설치형 앱)에서는 그 상태가 아예 오지 않았습니다** — 셸이 창을
`backgroundThrottling: false`로 만들면 Electron이 Page Visibility API를 끄고, 창을 트레이에
숨겨도 `visibilityState`가 `visible`로 남습니다(공식 문서에 그렇게 적혀 있습니다). 그 값
하나로 "보고 있는가"를 재던 기능이 **한 번도 동작하지 않은 채 배포됐습니다**(제보).

**규칙**: 플랫폼 API의 상태를 심어 테스트할 때는 "이 상태가 **대상 플랫폼에서 실제로
발생하는가**"를 먼저 확인하세요(그 API의 공식 문서 한 줄이면 됩니다 — 이번 건도 문서에
명시돼 있었습니다). 그리고 테스트의 **기본 상태를 실기기가 답하는 값으로** 두세요. 심을 수
있다는 것이 그 상태가 존재한다는 뜻은 아닙니다.

**곁들여**: 그래서 `hidden`을 신호로 쓰는 코드는 설치형 앱에서 전부 다르게 돕니다 — 이
저장소에서는 60초 주기 확인이 창을 닫아 둬도 계속 돌고(배지가 움직이는 이유), 업데이트
자동 적용의 `hidden` 인자가 늘 false입니다. 창이 숨었는지를 알아야 하면 **포커스**를 보세요
(`document.hasFocus()` — 셸의 그 설정과 무관합니다).

<a id="f7"></a>
### F7. jsdom은 `naturalWidth`가 **0**이라 그림 크기에 기댄 길을 통째로 건너뛴다

이미지 판에 배율을 붙이면서(제보 51-⑧) `ref` 갈래에서 `img.complete`면 원본 픽셀을
읽어 `setNat({w,h})`를 했다. jsdom은 그림을 재지 못해 `naturalWidth`가 늘 0이므로 그
갈래가 **한 번도 실행되지 않았고**, 공책 테스트 281건이 전부 초록이었다. 실브라우저에
올리자마자 `React #185`(Maximum update depth)로 판이 뜨지 않았다 — 인라인 `ref` 콜백은
렌더마다 새 함수라 매번 붙었다 떨어지고, 그때마다 **새 객체**를 상태에 넣어 렌더가
끝없이 돌았다. 수리는 둘: `ref`를 `useCallback`으로 고정하고, 값이 같으면 **같은 객체**를
돌려준다(`setNat((p) => (p && p.w === … ? p : {…}))`).

**규칙**: 그림·폰트·레이아웃을 재는 코드는 jsdom이 "조용히 건너뛴다". 그 길은 초록을
근거로 삼지 말고 **반드시 실브라우저로 한 번 열어 본다**.

<a id="f8"></a>
### F8. vitest에서 ⌘S로 확정해도 **마지막 커밋이 빠진 판**이 저장될 수 있다

공책 테스트의 `saveNow()`(⌘S)는 자동저장 디바운스를 건너뛰는 처방이지만, 조작이 커밋을
**두 번 이상** 만들면(예: `/질의` 지우기 + 종류 바꾸기) 마지막 `setDoc`이 리액트의 다음
렌더에서 계산되는 일이 있어 그때의 저장본에는 **앞의 커밋만** 들어 있다. 실측: 빈 줄에서
`/구분선`을 골랐는데 저장본이 `kind: 'p'`(runs만 비워진 판)였고, 화면(`data-note-kind`)은
이미 `hr`이었다 — 앱은 결백했고 **단정한 자리가 틀렸다**(A4의 vitest 판).

**규칙**: 저장본은 한 번 읽어 단정하지 않는다. 화면(`data-note-*`)으로 먼저 확인하고,
저장본은 `await waitFor(() => expect(saved(...)...).toBe(...))`로 **폴링**한다
(`toHaveLength` 같은 느슨한 조건이 먼저 통과해 버리면 그 뒤의 단정이 옛 값을 본다).

## G. 셸·프로세스

<a id="g1"></a>
### G1. `git checkout <file>`로 "복구"하지 않는다 — **세 번 재발**

임시로 코드를 되돌려 "수리 전 실패"를 확인한 뒤 `git checkout`으로 복구하면 **커밋하지 않은
구현이 통째로 날아갑니다.** 되돌리기 검증은 **문자열 치환 + 원복**(python·sed)으로 하세요.

<a id="g2"></a>
### G2. `pkill -f <문자열>`은 자기 셸을 문다

`pkill -f "http.server 8942"`는 그 문자열을 명령줄에 든 **내 셸까지** 죽입니다(exit 144).
서버는 PID를 들고 있다가 그것으로 끄세요(`pgrep -f … | head -1` → `kill $pid`).

> 세 번째 재발입니다. 패턴이 **지금 치고 있는 명령줄에도 들어 있다**는 것이 함정이라,
> "이번엔 짧은 패턴이니 괜찮겠지"가 통하지 않습니다.

<a id="g4"></a>
### G4. 이 컨테이너의 Electron은 `--no-sandbox`가 필요하다

root로 도는 환경이라 그냥 띄우면 **창이 뜨기 전에 죽습니다**:
`FATAL: Running as root without --no-sandbox is not supported` → SIGTRAP.
로그를 보지 않으면 "앱이 안 뜬다"로 오진합니다. 프로브는
`xvfb-run -a npx electron . --no-sandbox --user-data-dir=<빈 폴더>`로.

또 하나: 이 컨테이너에는 **알림 데몬이 없어** 메인 프로세스의
`Notification.isSupported()`가 `false`입니다 — 셸이 알림을 띄우는 경로는 여기서
"거절되는 것까지"만 확인할 수 있고, 실제로 뜨는지는 실기기의 몫입니다.

<a id="g3"></a>
### G3. lint는 **루트에서** 돌린다

`apps/web` 안에서만 돌리면 루트 eslint가 잡는 것(미사용 prop 등)을 놓쳐 **CI가 깨집니다.**
CI와 같은 `pnpm lint`·`pnpm typecheck`를 쓰세요.

## H. 진단하는 태도

- **시안 대조는 확대해서.** 원본 해상도로 눈대중하면 2px 차이를 "고쳤다"고 착각합니다
  (`border-radius: 999px`와 `15px`이 34px 상자에서 2px 차이였고, 그것을 고쳤다고 보고했다가
  "프리뷰가 이전과 동일하다"는 제보를 받았습니다). 5배로 확대해 **비율**을 재고, 색은 픽셀로 뽑으세요.
- **증상이 바뀌면 어느 번들이 떠 있는지 먼저 확인.** 설정 › 버전 확인의 빌드 시각·커밋 7자가
  그 답입니다. 이 확인 한 줄이 30분을 아낀 적이 있습니다.
- **관측 가능한 것과 불가능한 것을 갈라 보고한다.** "확인할 수 없다"와 "되지 않았다"는 다른
  말입니다. 간접 신호(배포 상태 API 등)의 침묵을 결론으로 쓰지 마세요.
- **남의 라이브러리·API의 기본값은 소스에서 확인한다.** 기억으로 답하다 같은 자리를 두 번
  틀렸습니다(`@supabase/auth-js`의 기본 `flowType`은 `implicit`인데 PKCE로 가정했습니다).
  확인한 사실은 **코드에 못박아** 다음 사람이 다시 틀리지 않게 하세요.

## 프로브를 쓰기 전 체크리스트

1. 시드를 심는가 → **가드**했는가([A1](#a1)), **실물 모양**인가([A3](#a3)), 리로드가 아니라 **새 페이지**인가
1b. 결과를 **저장본**에서 읽는가 → 자동저장은 늦는다([A4](#a4)) — DOM에서 재거나 값이 바뀔 때까지 폴링
2. 좌표를 쓰는가 → 화면 **안쪽**인가([D1](#d1)), 그 자리에 **다른 것**이 없는가([D4](#d4)), 뷰포트 rect를 더했는가([D2](#d2))
3. 잴 것이 좌표·스크린샷인가 → **전이가 끝난 뒤**인가([C1](#c1))
4. 이벤트를 합성하는가 → 사이를 **띄웠는가**([B2](#b2)), 수정 키는 `modifiers`인가([B3](#b3))
5. 스크롤바·OS 알림·네이티브인가 → **xvfb headed**가 필요한가([E1](#e1), [E2](#e2), [E4](#e4))
6. 날짜를 쓰는가 → **DOM에서** 읽었는가([E3](#e3))
7. 플랫폼 상태(`visibilityState` 등)를 심는가 → 그 상태가 **대상 플랫폼에서 실제로 나는가**([F6](#f6))
8. 실패했는가 → **사용자가 손으로 해도 같은 일이 나는가**(첫 번째 규칙)

새 함정을 만나면 이 문서에 한 줄 더하세요. 같은 함정을 두 번 밟는 것이 가장 비쌉니다 —
여기 실린 것 중 셋은 **네 번, 세 번, 두 번** 재발했습니다.
